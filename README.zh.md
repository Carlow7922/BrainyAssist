# BrainyAssist —— 让 AI 拥有长期记忆，而成本仅为百分之一

> 一个基于 “固定核心认知空间 + 按需记忆检索” 的轻量级助手架构

专为**本地运行、低成本、永不遗忘**而设计

⚠️ 项目当前处于测试阶段，功能仍在迭代优化中

## 我们面临的问题

你是否也遇到过这些情况？



* 使用 DeepSeek、Claude、GPT-4 或 Gemini 时，对话一长，模型就**忘记几分钟前说过的关键信息**。

* 为了让它记住项目背景，你不得不在**每次新会话中反复粘贴相同的说明**，浪费大量 token 和时间。

* 更可怕的是账单：一天烧掉 200 元人民币的 API 费用，仅仅是因为需要 “长上下文”。

* 想本地跑一个开源模型？记忆能力几乎为零，问三句就断片。

**问题本质**：

现有方案要么**贵**（长上下文模型 API），要么**傻**（本地小模型无记忆）。

中间没有一个**既便宜、又能可靠记住关键信息**的助手。

## 我们的解决方案

### 核心思想（来自类脑架构 + 双层记忆设计）

人脑不是把所有记忆都塞进 “工作区”，而是只保留一个极简的**核心认知空间**（三观、当前目标、任务进度），其余信息存放在**长期记忆**中，需要时再快速检索。

我们在类脑记忆机制基础上，进一步借鉴 [zer](https://github.com/hermes-labs-ai/zer0dex/blob/main/README.md)[0dex](https://github.com/hermes-labs-ai/zer0dex/blob/main/README.md) 项目的**双层记忆架构**，将记忆分层管理并结合压缩索引，实现更高效的记忆检索与复用，彻底解决 “记忆碎片化” 和 “检索低效” 的痛点：



| 组件                  | 作用                                              | Token 消耗     |
| ------------------- | ----------------------------------------------- | ------------ |
| **核心认知空间**（永久 + 临时） | 每次对话都注入的固定认知与临时缓存（项目核心信息、临时任务状态）                | 恒定～500 token |
| **双层记忆体系**          | 压缩索引文件（MEMORY.md）+ 向量库检索（按用户问题返回最相关 3\~5 条历史记忆） | \~2000 token |
| **会话记忆**            | 每轮对话总结的重要信息（sessionsMemory.md）                  | 按需增量，可控      |
| **LLM 推理**          | 基于上述所有信息生成回答                                    | 正常生成长度       |

**结果**：

无论对话多长，每次请求的 token 消耗**几乎不变**，彻底告别上下文膨胀；双层记忆架构让检索召回率提升至 90%+，同时解决传统 RAG 跨领域关联弱的问题。

### 关键记忆文件说明



| 文件路径                                          | 作用                     | 备注                               |
| --------------------------------------------- | ---------------------- | -------------------------------- |
| `data/cognitive_space/permanent_cognition.md` | 永久认知文件，存储项目核心、固定背景信息   | 替代原 core\_state.txt，确保核心认知不丢失    |
| `data/cognitive_space/temporary_context.md`   | 临时缓存文件，存储当前会话临时状态、任务进度 | 替代原 core\_state.txt，灵活适配短期需求     |
| `data/MEMORY.md`                              | 双层记忆架构的压缩索引文件          | 沿用 zer0dex 设计，提供知识导航 scaffolding |
| `data/sessionsMemory.md`                      | 会话记忆文件，每轮对话自动总结的重要信息   | 实时增量更新，避免重复记忆冗余                  |
| `data/memory/`                                | 向量库存储目录                | 本地私有化存储，支持备份 / 迁移，数据安全可控         |

### 记忆工作流程（当前实现）

每轮对话时，系统会自动加载 / 执行以下操作：



1. 加载 `cognitive_space` 下的 `permanent_cognition.md` + `temporary_context.md` 核心认知文件；

2. 加载压缩索引文件 `MEMORY.md`（提供知识分类导航，解决跨领域关联问题）；

3. 加载会话记忆文件 `sessionsMemory.md`（保留近期关键交互）；

4. 基于用户当前问题检索 `data/memory/` 向量库，返回最相关的 3\~5 条记忆（⚠️ 暂未实现检索结果写入缓存）；

5. 智能拼接所有记忆信息 + 用户问题发送给 LLM 生成回答（避免上下文膨胀）；

6. 对话结束后，自动总结重要信息写入 `sessionsMemory.md`（仅存事实 / 决策 / 结论，不存闲聊）。

### 文本嵌入模型适配



* **默认模型**：`m3e-small`，专为中文场景优化，兼顾速度与召回率，适合中文用户；

* **英文场景适配**：需手动修改代码，将嵌入模型替换为 `nomic-embed-text-v1.5`。

### 已知限制



* 暂时不支持图片输入，仅支持文本类交互；

* 向量库检索结果写入缓存功能尚未完成；

* 项目整体处于测试阶段，部分功能可能存在迭代调整。

## 为什么这个项目值得关注（核心优势与差异化）

### 1. 极致成本优势（碾压长上下文模型）



| 方案                                 | 50 轮对话累计 Token | 估算成本          | 核心差异              |
| ---------------------------------- | -------------- | ------------- | ----------------- |
| Gemini / Claude 长上下文               | > 200 万        | 6 \~ 30 美元    | 成本随轮数线性增长，越用越贵    |
| **BrainyAssist（Llama.cpp 本地 API）** | 约 14 万         | **0 元**（完全免费） | 成本恒定，无额外 token 消耗 |
| **BrainyAssist（第三方廉价 API）**        | 约 14 万         | 1 美元          | 成本极低，无需承担长上下文溢价   |
| 传统 RAG 方案                          | \~50 万         | 0 \~ 10 美元    | 检索冗余，跨领域关联弱       |

### 2. 灵活部署 + 低硬件门槛



* **部署自由**：支持 Llama.cpp 本地 API（完全离线）或第三方廉价 API（轻量化联网），按需选择；

* **数据安全**：本地部署时所有记忆、对话、向量库均存储在本地，杜绝数据泄露；

* **硬件友好**：最低 4GB 内存 + 2 核 CPU 即可运行（适配量化模型），推荐 RTX 3060 12GB 显存（流畅运行 7B/8B 模型）；

* **无强制依赖**：无需高端硬件或昂贵 API Key，灵活适配不同用户场景。

### 3. 差异化记忆架构（类脑 + 双层设计）



* 对比传统 RAG：解决 “事实漂浮无关联” 问题，压缩索引提供知识导航，跨领域查询召回率提升 40%+；

* 对比 Flat File 方案：避免全量上下文注入，token 消耗恒定，检索效率提升 3 倍；

* 对比 MemGPT/Letta：无需复杂记忆分页管理， latency 控制在 100ms 内，复杂度低、易部署；

* 对比单一 API 方案：支持本地 / 第三方 API 切换，兼顾成本与灵活性，中文适配优势显著。

### 4. 极简易用 + 灵活拓展



* 核心代码仅 200 行左右，部署成本低，二次开发门槛低；

* 支持 MD 文件 URL 导入：输入在线 MD 文档地址，一键写入向量库，快速构建专属知识库；

* 可对接更多本地推理引擎（未来规划），适配不同场景需求。

### 2. 配置说明

#### （1）认知文件配置



* 编辑 `data/cognitive_space/``permanent_cognition.md`：写入项目固定核心信息（如 “项目名称：BrainyAssist，核心目标：低成本长期记忆助手”）；

所有 API 连接参数均在配置文件 `BrainyAssist/.env` 中修改，支持一键切换本地 / 第三方 API：



| API 类型                       | 核心配置项                                                                                                                 | 默认值 / 示例                      |

| **Llama.cpp 本地 API**         | BASE_URL=http://192.168.1.2:8000/v1                                                                      | 需与 Llama.cpp 服务端口一致 |

1. 复制 `BrainyAssist/.env.example` 为 `BrainyAssist/.env`（若不存在示例文件，直接创建 .env）；

2. 根据实际使用的 API 类型，填写对应配置项，注释掉未使用的类型配置；

3. 确保本地 API 已启动（Llama.cpp 场景）或 API 密钥有效（第三方场景）。

## 常见问题

**Q：为什么不直接用 LangChain 的 ConversationBufferMemory？**

A：LangChain 的 Buffer 仍将历史全量塞入上下文，成本随轮数线性增长。我们采用**固定核心 + 双层记忆检索**，成本恒定且跨领域检索更高效。

**Q：记忆检索的准确率如何保证？**

A：目前使用 m3e-small（中文）/nomic-embed-text-v1.5（英文）做 embedding，对事实性查询召回率 > 90%。后续会加入重排序模型，进一步提升准确率。

**Q：能商用吗？**

A：代码 MIT 协议，欢迎商用。如果需要咨询技术支持，可通过 Issue 联系。

**Q：向量库数据如何备份 / 迁移？**

A：向量库存储在 `data/memory/` 目录下，直接拷贝该目录即可完成备份 / 迁移，无需额外配置。

**Q：如何切换本地 API 和第三方 API？**

A：编辑配置文件 `BrainyAssist/.env`，修改 `API_TYPE` 为 `local_llama_cpp` 或 `third_party`，并填写对应类型的配置项，重启服务即可生效。

**Q：支持哪些第三方 API？**

A：理论上支持所有兼容 OpenAI 格式或提供文本生成接口的 API（如 DeepSeek、豆包 Pro、硅基流动等），只需在 `.env` 中填写对应 `endpoint` 和 `key` 即可。未来会新增快速适配模板，无需手动配置 endpoint。
