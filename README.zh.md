# BrainyAssist —— 让 AI 拥有长期记忆，而成本仅为百分之一

> 一个基于“固定核心认知空间 + 按需记忆检索”的轻量级助手架构  
> 专为**本地运行、低成本、永不遗忘**而设计

## 我们面临的问题

你是否也遇到过这些情况？

- 使用 DeepSeek、Claude、GPT-4 或 Gemini 时，对话一长，模型就**忘记几分钟前说过的关键信息**。
- 为了让它记住项目背景，你不得不在**每次新会话中反复粘贴相同的说明**，浪费大量 token 和时间。
- 更可怕的是账单：一天烧掉 200 元人民币的 API 费用，仅仅是因为需要“长上下文”。
- 想本地跑一个开源模型？记忆能力几乎为零，问三句就断片。

**问题本质**：  
现有方案要么**贵**（长上下文模型 API），要么**傻**（本地小模型无记忆）。  
中间没有一个**既便宜、又能可靠记住关键信息**的助手。

## 我们的解决方案

### 核心思想（来自类脑架构）

人脑不是把所有记忆都塞进“工作区”，而是只保留一个极简的**核心认知空间**（三观、当前目标、任务进度），其余信息存放在**长期记忆**中，需要时再快速检索。

我们将这个机制工程化：

| 组件 | 作用 | Token 消耗 |
| :--- | :--- | :--- |
| **临时核心认知空间** | 每次对话都注入的固定状态（项目名、当前任务、工具说明） | 恒定 ~500 token |
| **外部记忆库（向量检索）** | 按用户问题检索最相关的 3~5 条历史记忆 | ~2000 token |
| **LLM 推理** | 基于上述信息生成回答 | 正常生成长度 |

**结果**：  
无论对话多长，每次请求的 token 消耗**几乎不变**，彻底告别上下文膨胀。

### 架构来源

- 神经科学中的**工作记忆 vs 长期记忆**区分
- 你的 **BrainDecoupledLLM-MVP** 已验证可行性（[GitHub 链接](https://github.com/Carlow7922/BrainDecoupledLLM-MVP/tree/main)）
- 借鉴了 RAG 和固定系统提示词的成熟实践，但进行了**类脑的模块化整合**

### 可行性分析

- ✅ 已有 MVP 证明：固定核心认知 + 外部检索，能实现多轮不遗忘。
- ✅ 向量数据库（Chroma、LanceDB）成熟稳定，单机可处理百万级记忆。
- ✅ 本地模型（Llama 3 8B、Qwen 2.5 7B）在消费级显卡（RTX 3060）可流畅运行，完全脱离云端 API。
- ✅ 即使使用廉价 API（豆包 Pro、硅基流动免费额度），单次请求成本可控制在 **<0.01 元**。

### 实现思路（极简，即可运行）

1. **初始化**：创建 `core_state.txt`，写入项目的固定认知（如“项目名称：BrainyAssist，当前任务：实现记忆检索”）。
2. **每轮对话**：
   - 加载 `core_state.txt` 作为系统提示词。
   - 用用户的输入去向量库检索相关记忆。
   - 拼接（核心认知 + 检索记忆 + 用户问题）发送给 LLM。
   - 将 LLM 的回答展示给用户。
   - （可选）让用户或自动规则将新知识存入记忆库。
3. **记忆管理**：  
   - 写入：只保存事实、决策、结论（1~2 句话），不存闲聊。  
   - 检索：用 embedding 模型（本地或 API）计算相似度，返回 top‑K。

> 完整代码约 200 行 Python，依赖 chromadb、requests、一个 embedding 模型。

## 为什么这个项目值得关注

### 1. 极大的成本降低

| 方案 | 50 轮对话累计 Token | 估算成本 |
| :--- | :--- | :--- |
| Gemini / Claude 长上下文 | > 200 万 | 6 ~ 30 美元 |
| **BrainyAssist（本地 Llama）** | 约 14 万 | **0 元**（完全免费） |
| **BrainyAssist（廉价 API）** | 约 14 万 | < 0.1 美元 |

### 2. 真正的本地私有化

- 所有记忆和对话存储在你自己电脑上。
- 可对接 Ollama、llama.cpp 等本地推理引擎，**不需要任何 API Key**。
- 无需担心数据泄露或被商用模型收集。

### 3. 极低的硬件门槛

- **最低配置**：4GB 内存 + 2 核 CPU（使用 Qwen 1.5B 或 DeepSeek V2 Lite 量化版）。
- **推荐配置**：RTX 3060 12GB 显存（运行 Llama 3 8B 或 Qwen 2.5 7B）。

## 快速开始（给自己用，也给你参考）

> 当前阶段，项目以**解决作者自身需求**为主，同时开源供有缘人借鉴。

```bash
# 1. 克隆仓库
git clone https://github.com/Carlow7922/BrainyAssist.git
cd BrainyAssist

# 2. 安装依赖
pip install chromadb sentence-transformers requests

# 3. 配置你的 core_state.txt（示例见 config/core_state.example.txt）

# 4. 运行对话脚本
python chat.py --model local  # 使用本地 Ollama 模型
# 或
python chat.py --model api --endpoint https://api.deepseek.com --key YOUR_KEY
```

详细使用说明请查看 [USAGE.md](./USAGE.md)。

## 常见问题

**Q：为什么不直接用 LangChain 的 ConversationBufferMemory？**  
A：LangChain 的 Buffer 仍将历史全量塞入上下文，成本随轮数线性增长。我们采用**固定核心 + 按需检索**，成本恒定。

**Q：记忆检索的准确率如何保证？**  
A：目前使用 sentence-transformers/all-MiniLM-L6-v2 做 embedding，对事实性查询召回率 > 90%。后续会加入重排序模型。
